Design exploration

Statement import — three redesign concepts

Today's flow asks for a lot of small confirmations and never shows the user the result of importing until after it's done. These three concepts keep the matching engine as-is — exact-date-and-amount matches, ambiguity stays manual, near-misses stay explicit — but change how much the user has to touch and how clearly the outcome is shown.

All three are loaded with the same ~50-row June dataset (26 matched · 8 bills · 2 transfer pairs · 3 incoming · 4 new · 5 needing a decision) so they can be compared at realistic scale.

Why a 50-row month breaks the current flow

  • • The review carousel turns into ~15–25 Prev/Next/Accept clicks — the bulk of the month is confident matches nobody needs to see.
  • • There's no way to say “show me only the rows you're unsure about”.
  • • The 45 settled rows and the 5 real decisions carry the same visual weight.

The redesign goal at scale: make the 90% disappear and put the 5 exceptions front and centre.

Why the current flow feels convoluted

  • • Per-file add → then a separate Find matches step.
  • • One-at-a-time review carousel (“1 of 19”, Prev / Skip / Accept) — confident matches still need a click each.
  • • A third screen for leftovers, bills, and unaccounted rows.
  • • The effect of importing is buried in a summary and on Home only as “Imported · £X · N transactions”.

The concepts

Fewest taps

1 · Auto-first workspace

Matching runs on upload. One scrolling page with a live “what this import does” bar; only the 5 ambiguous rows are surfaced, the other 45 collapse into inspectable groups.

~7 taps for 50 rows (upload ×2, resolve 5, import). Removes Find matches, the carousel, and the wizard.
Most explicit

2 · Effect-first cockpit

All 50 rows on one grid with safe defaults pre-selected; a confidence filter jumps to the 5 exceptions, and a sticky panel shows before → after.

~9 taps for 50 rows (upload ×2, accept bulk, resolve 5, import). Best audit trail.
Mobile-first

3 · Card inbox

A 50-row statement collapses to “5 left to sort”. Auto-settled rows never appear as tasks; each decision is one card. Ends on a clear “balanced” state.

~7 taps for 50 rows (upload ×2, 5 cards, import). Lowest cognitive load on a phone.

What none of these sacrifice

  • • Exact-amount + exact-date matches still auto-link; near-misses never auto-link.
  • • Same-amount collisions always require a human pick.
  • • Transfers, netted groups, and expected bills keep their current rules.
  • • Every auto-decision stays inspectable and reversible (no silent data loss).
  • • Leftover logged spends and unaccounted rows are still explicitly resolved.
  • • Import stays reversible after the fact.

Recommendation

Concept 2 as the desktop default, Concept 3 as the phone default, sharing Concept 1's auto-run-on-upload and live outcome bar. The cockpit's before → after panel is what fixes the “unclear effect” problem; the inbox is the same model with decision cards stacked for small screens.
